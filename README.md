# 「Vibe与开源」赛道评分标准

---

## 一、赛道定位

- 面向有一定基础、愿意动手的新人，不面向零基础普及。
- 不追求“高质量开源贡献”，而是看：
  - 一周内有没有真实增量；
  - 项目/PR 能不能跑、能不能展示；
  - 能不能讲清自己做了什么、怎么学会的；
  - 有没有持续动手和解决问题的潜力。
- 闭源项目也可接受，但必须可验证。
- CI、工作流、测试、License、部署、star、合并等只做低权重或加分，不作为硬门槛。

---

## 二、通用规则

### 硬门槛

- 必须证明是 **训练营期间** 的真实增量：commit、PR、diff、release、录屏等。
- 必须能 **展示或录屏**：项目能跑，或 PR 有实际改动。
- 必须能讲清：**你做了什么、怎么做的、学到什么**。不答辩，但展示里要讲。
- 闭源项目：录屏 + 可运行演示 + 关键 diff/commit，三选二即可。

### 低权重原则

- CI / 工作流 / 测试 / License / 部署 / star / 合并：**最多 5～10 分，或只作加分**。
- 重点看：**完成度、真实增量、可运行、代码能读懂、学习与表达**。

### 防作弊

- 刷 typo、改 README、纯格式化 PR，不算高质量 PR。
- 一次性上传整个项目，无训练营期间迭代记录，降档。
- AI 生成无审查、无法解释代码，扣分。
- 抄袭、伪造贡献，直接取消。

---

## 三、评分类型与标准

三类各满分 100 分，便于单独评奖；如需混排，建议用难度系数校准。

---

### 类型一：PR 贡献类（给别人项目发 PR）

| 维度 | 分值 | 观察点 |
|---|---:|---|
| 真实性与合规 | 10 | PR 在训练营期间；非刷量、非纯 typo/README |
| PR 难度与项目理解 | 20 | 是否读懂项目；改动是否有实际意义 |
| 训练营期间投入与迭代 | 15 | 持续修改、回应 review、多次 commit |
| 代码质量与可读性 | 20 | 能看懂、风格一致、边界处理合理 |
| PR 描述与沟通 | 10 | 描述清楚、关联 issue、礼貌沟通 |
| 合并 / 维护者反馈 | 10 | 已合并高分，但**不合并也不直接淘汰** |
| 展示与学习表达 | 15 | 能讲清难点、怎么学会的、后续计划 |
| **合计** | **100** | |

**加分最多 +5：**
- 多个有效 PR
- 被维护者感谢
- 修复长期 issue
- 补充测试 / CI

**扣分：**
- 刷 PR、无意义改动：-10～-30
- 无法解释代码：-20
- 抄袭他人 PR：取消资格

---

### 类型二：新开源项目类（一周从 0 到 1）

| 维度 | 分值 | 观察点 |
|---|---:|---|
| 完成度与可运行 | 20 | 能跑、能演示、核心功能闭环 |
| 核心功能与个人实现 | 20 | 主要代码是不是自己写的，能否讲清 |
| 训练营期间迭代 | 15 | 一周内有持续 commit、issue、版本记录 |
| 代码可读性与结构 | 15 | 目录清楚、命名合理、能读懂 |
| 文档与展示 | 15 | README、安装步骤、截图、Demo 流畅 |
| 技术难度 / 学习跨度 | 10 | 是否学到新东西，是否解决真实问题 |
| 工程规范（测试 / CI / License） | 5 | **低权重，锦上添花** |
| **合计** | **100** | |

**加分最多 +5：**
- 部署上线
- 有 CI
- 有 License
- 被 star / fork / issue / PR

**扣分：**
- 一次性上传，无过程：-15
- 无法运行：-20
- 无 License：-5
- 抄袭：取消资格

---

### 类型三：旧项目 / 闭源项目维护展示类

| 维度 | 分值 | 观察点 |
|---|---:|---|
| 训练营期间增量贡献 | 25 | 这一周新增功能、重构、修 bug、优化 |
| 增量可验证性 | 15 | commit / diff / release / 录屏；闭源也能验证 |
| 个人角色与项目理解 | 15 | 你负责哪部分，能否讲清架构 |
| 改动代码质量与可读性 | 15 | 改动是否合理、可维护、能读懂 |
| 过程管理与迭代 | 10 | issue、commit、更新日志、任务拆解 |
| 展示与学习表达 | 15 | Demo 清楚、能讲难点和取舍 |
| 工程规范（测试 / CI 等） | 5 | **低权重** |
| **合计** | **100** | |

**加分最多 +5：**
- 训练营期间开源化
- 发 Release
- 写技术文档 / 博客
- 有用户反馈
- 有测试 / CI

**扣分：**
- 纯展示旧成果：-15
- 无法证明一周内增量：-20
- 闭源但拒绝录屏 / 演示：-20
- 无法解释核心代码：-20
